# دیتابیس، کوئری نصب و تغییر پروژهٔ Supabase

این راهنما هیچ انتقال واقعی را خودکار اجرا نمی‌کند. قبل از هر تغییر مقصد، بک‌آپ قابل بازیابی از داده‌ها و تصاویر داشته باشید.
همهٔ دستورهای npm/node زیر از ریشهٔ ریپو، کنار package.json اجرا می‌شوند.

## حالت اول: پروژهٔ Supabase تازه و بدون دادهٔ قدیمی

۱. در SQL Editor پروژهٔ مقصد، نقش postgres را انتخاب کنید.
۲. کل محتوای [supabase/SETUP.sql](../supabase/SETUP.sql) را اجرا کنید. فایل آمادهٔ کپی است؛ placeholder یا کلید لازم ندارد.
۳. [supabase/VERIFY.sql](../supabase/VERIFY.sql) را اجرا کنید.

خروجی موردانتظار:
- ۱۲ جدول داخل app_private با RLS روشن.
- مجوز SELECT و دسترسی schema برای anon/authenticated برابر false.
- قید appointments_no_overlap معتبر باشد.
- index users_supabase_auth_id موجود باشد.
- bucket با id=business-media، public=true و سقف ۵۲۴۲۸۸۰ بایت.
- شمارنده‌های جدول‌ها روی پروژهٔ تازه صفر باشند.

این SQL برای ساخت/به‌روزرسانی schema است، نه انتقال رکورد یا Auth یا تصویر.
هر سه migration داخل آن عیناً جمع شده‌اند؛ یک تست، همگام‌ماندن فایل با migrationها و اجرای دوباره را بررسی می‌کند.
دستور معادل در ترمینال، در صورت تنظیم env مقصد: npm run db:migrate.

۴. env مقصد را طبق [راهنمای دیپلوی](../DEPLOYMENT.md) تنظیم کنید. DATABASE_URL، SUPABASE_URL، کلید عمومی Auth و کلید Secret Storage باید متعلق به یک پروژه باشند.
۵. Auth، SMTP و callbackها را تنظیم کنید؛ SQL به‌تنهایی ورود و ارسال ایمیل را فعال نمی‌کند.

## حالت دوم: فقط تغییر URI در همان پروژه

اگر فقط از Session pooler به Transaction pooler همان پروژه جابه‌جا می‌شوید، داده‌ها منتقل نمی‌شوند و نباید دوباره import کنید.
DATABASE_URL را با URI رسمی Connect همان پروژه عوض کنید؛ رمز را encode کنید، SSL=require باقی بماند.
این برنامه prepare=false و max=1 دارد و برای runtime سرورلس با Transaction pooler تنظیم شده است.
برای نصب schema از SQL Editor یا اتصال Direct/Session استفاده کنید؛ runtime را پس از نصب روی Transaction بگذارید.
تغییر env در Vercel نیاز به دیپلوی تازه دارد. [اتصال Supabase](https://supabase.com/docs/guides/database/connecting-to-postgres)، [env در Vercel](https://vercel.com/docs/environment-variables).

## حالت سوم: انتقال نسخهٔ قدیمی MongoDB به Supabase

این مسیر برای بک‌اند قدیمی Python/MongoDB است که اکنون از پروژه خارج و در بک‌آپ محلی نگه‌داری شده است؛ برای Supabase به Supabase از بخش بعد استفاده کنید.

۱. از MongoDB و backend/uploads بک‌آپ بگیرید.
۲. مقصد تازه را با SETUP.sql آماده کنید.
۳. فقط در env محلی، MONGO_URL و DB_NAME مبدأ، به‌علاوهٔ تنظیمات Supabase مقصد را قرار دهید.
اگر تصاویر URL مطلق قدیمی دارند، LEGACY_UPLOAD_ORIGINS را با مبدأهای واقعی، جداشده با ویرگول وارد کنید.
پوشهٔ backend/uploads دیگر داخل ریپو نیست. LEGACY_UPLOAD_DIR را صریحاً به مسیر کامل uploads در بک‌آپ قدیمی تنظیم کنید؛ ابزار انتقال بدون این مقدار اجرا نمی‌شود. مسیر مبدأ بیرون ریپو باقی می‌ماند و چیزی از آن پاک نمی‌شود.
۴. ابتدا بررسی فقط‌خواندنی:

```powershell
node scripts/import-mongo.mjs
```

فایل گم‌شده، مقصد متفاوت یا دادهٔ ناسازگار را پیش از ادامه حل کنید.
۵. نوشتن نسخهٔ قدیمی را متوقف کنید؛ پس از تأیید بک‌آپ و مقصد، انتقال را صریحاً اجرا کنید:

```powershell
node scripts/import-mongo.mjs --apply --maintenance-confirmed
node scripts/import-mongo.mjs --verify
```

این ابزار منبع را پاک نمی‌کند و رکورد متفاوت مقصد را بازنویسی نمی‌کند. شناسه‌ها و تنظیمات تو‌در‌تو حفظ می‌شوند.
درج SQL تراکنشی است؛ شکست انتقال SQL، تصاویر کپی‌شده را خودکار حذف نمی‌کند. مقصد تازه استفاده کنید.
۶. انتقال حساب‌ها و bcrypt به Auth مرحلهٔ جداست:

```powershell
npm run auth:migrate
npm run auth:migrate -- --apply --maintenance-confirmed
```

دستور اول فقط بررسی است؛ دستور دوم به Auth مقصد می‌نویسد. قبل از اجرای دوم گزارش را بررسی کنید.
ایمیل تأییدنشده خودکار تأیید نمی‌شود؛ تعارض حساب نیازمند بررسی است. [جزئیات Auth](../SUPABASE_AUTH.md).
۷. VERIFY.sql، شمارنده‌ها و ورود/رزرو/تصاویر را در مقصد بررسی کنید؛ سپس ترافیک را جابه‌جا کنید.
مبدأ را تا پایان بازهٔ بازگشت نگه دارید.

## حالت چهارم: انتقال یک پروژهٔ Supabase موجود به پروژهٔ دیگر

فقط عوض‌کردن DATABASE_URL، یا اجرای SETUP.sql، اطلاعات قبلی را منتقل نمی‌کند.
Auth، جدول‌های برنامه و فایل‌های Storage سه بخش مجزا هستند. ابزار import-mongo.mjs برای این سناریو نیست.

ترتیب امن:
۱. ابتدا روی پروژهٔ آزمایشیِ خالی تمرین و از هر دو مقصد و مبدأ بک‌آپ بگیرید.
۲. طبق [راهنمای رسمی Backup/Restore](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore)، dump و restore پروژه را انجام دهید؛ مطمئن شوید schema سفارشی app_private هم در انتقال هست. مسیر رسمی Dashboard Restore یا CLI را مطابق امکانات پروژه انتخاب کنید.
۳. انتقال Auth باید شناسهٔ کاربران را حفظ کند؛ users.data.supabase_auth_id به همان شناسه‌ها وابسته است. SQL نصب، کاربران Auth را ایجاد نمی‌کند. فقط انتقال جدول app_private.users کافی نیست.
۴. فایل‌های واقعی business-media را با حفظ نام و مسیر منتقل کنید؛ بک‌آپ دیتابیس به‌تنهایی کپی بایت‌های تصاویر نیست. مقصد دارای فایل هم‌نام را بدون مقایسه بازنویسی نکنید.
۵. آدرس‌های تصاویر ذخیره‌شده، مطلق و وابسته به hostname قبلی Supabase هستند. بعد از کپی فایل‌ها، آدرس‌ها باید کنترل‌شده به hostname مقصد بازنویسی و صحت تک‌تک تصاویر بررسی شوند. ابزار خودکار PostgreSQL-to-PostgreSQL و بازنویسی این آدرس‌ها در این مخزن وجود ندارد؛ بدون این مرحله، پروژهٔ قبلی را خاموش نکنید.
۶. تنظیمات غیر SQL مثل SMTP، Email provider، URL Configuration و کلیدهای API مقصد را دوباره بررسی کنید.
۷. هنگام انتقال نهایی، نوشتن مبدأ را متوقف کنید؛ نسخهٔ نهایی را منتقل و VERIFY.sql و شمارنده‌ها را در هر دو پروژه مقایسه کنید.
۸. همهٔ envهای مقصد را با هم در Vercel عوض و Redeploy کنید؛ URI دیتابیس جدید را با Auth/Storage قدیمی مخلوط نکنید.
۹. کاربران پس از جابه‌جایی پروژه باید دوباره وارد شوند. تا تأیید ورود، تصاویر، صفحه‌ها، لینک‌ها و رزروها، مبدأ و بک‌آپ را نگه دارید.

این عملیات روی دادهٔ موجود بدون بررسی مبدأ/مقصد نباید با یک کوئری عمومی اجرا شود؛ به همین دلیل هیچ دستور DROP/TRUNCATE یا جایگزینی سراسری URL بدون اعتبارسنجی در راهنما نیست.

## بازگشت اضطراری

تنظیمات قبلی را در جای امن داشته باشید، نه در گیت. اگر هنوز مقصد نوشتن واقعی ندارد، env/دیپلوی قبلی را برگردانید.
اگر پس از cutover در مقصد رزرو یا کاربر تازه ایجاد شده، بازگشت ساده می‌تواند آن تغییرات را گم کند؛ ابتدا نوشتن را متوقف و داده‌های جدید را تطبیق دهید.
تعویض رمز/کلید افشاشده را برگردانیدنی فرض نکنید؛ کلید معتبر جدید را در همهٔ مصرف‌کننده‌ها تنظیم کنید.
