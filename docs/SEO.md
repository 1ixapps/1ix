# سئوی وانیکس و کارهای بعد از انتشار

## اصلاحات فنی داخل پروژه

- صفحهٔ اصلی و تعرفه‌ها با همان کامپوننت‌های واقعی در سرور رندر می‌شوند؛ متن، H1، لینک‌ها و تعرفه‌ها پیش از اجرای JavaScript در HTML حضور دارند.
- صفحهٔ /u/username در سرور فقط از اطلاعات منتشرشده و تعلیق‌نشده خوانده می‌شود. عنوان، توضیح و کلمات انتخابی صاحب کسب‌وکار از بخش seo استفاده می‌شوند.
- خواندن اطلاعات برای metadata و sitemap شمارندهٔ بازدید را تغییر نمی‌دهد. ثبت بازدید همچنان از مسیر عمومی موجود انجام می‌شود.
- عنوان، توضیح، canonical، Open Graph و Twitter Card برای خانه، تعرفه‌ها و صفحات کسب‌وکار مستقل‌اند.
- تصویر اشتراک‌گذاری PNG با اندازهٔ ۱۲۰۰×۶۳۰ در /share-image تولید می‌شود؛ به‌جای تکیه بر SVG فاوآیکون.
- دادهٔ ساختاریافتهٔ Organization، WebSite و SoftwareApplication روی صفحهٔ اصلی وجود دارد؛ امتیاز، مشتری، نظر یا آمار ساختگی اضافه نشده است.
- /robots.txt و /sitemap.xml به‌صورت واقعی وجود دارند.
- sitemap فقط خانه، تعرفه‌ها و صفحات منتشرشدهٔ غیرتعلیق را فهرست می‌کند؛ حداکثر ۲۰هزار صفحهٔ کسب‌وکار در نسخهٔ فعلی. در مقیاس بزرگ‌تر باید sitemap index و صفحه‌بندی اضافه شود.
- اختلال دیتابیس در ساخت sitemap با ۵۰۳ و Retry-After پاسخ می‌گیرد؛ نبود اطلاعات به‌اشتباه به‌عنوان حذف صفحات گزارش نمی‌شود.
- پنل، مدیریت، صفحات ورود/ثبت‌نام/بازیابی و لینک‌های انتقال، noindex دارند. Previewهای Vercel نیز noindex هستند.
- آدرس ناشناخته و صفحهٔ منتشرنشده پاسخ HTTP ۴۰۴ واقعی می‌گیرند؛ متن خطا در یک صفحهٔ ۲۰۰ نمایش داده نمی‌شود.
- ناوبری داخل برنامه هم متادیتا را به‌روز می‌کند و دادهٔ ساختاریافتهٔ صفحهٔ قبلی باقی نمی‌ماند.
- فارسی/RTL، فونت محلی، فاوآیکون و canonical دامنه حفظ شده‌اند.

## موضوع‌های هدف

| مسیر | نیت جست‌وجو |
|---|---|
| خانه | وانیکس، سایت‌ساز فارسی کسب‌وکار، ساخت صفحه کسب‌وکار، لینک کوتاه، لینک بیو، نوبت‌دهی آنلاین |
| تعرفه‌ها | تعرفه وانیکس، قیمت سایت‌ساز، هزینه نوبت‌دهی آنلاین |
| صفحهٔ هر کسب‌وکار | نام واقعی کسب‌وکار، خدمات، دسته و توضیحات اختصاصی همان مجموعه |

این‌ها موضوع‌های مرتبط با محصولند، نه نتیجهٔ تحقیق حجم جست‌وجو یا تضمین رتبه.
meta keywords حفظ و مرتب شده، اما زیادکردن آن به‌تنهایی استراتژی رتبه‌گرفتن نیست. متن مفید و منحصربه‌فرد، HTML قابل‌خزش، عنوان و توضیح درست، تجربهٔ واقعی کاربران و اعتبار دامنه اهمیت دارند.
عنوان را خوانا نگه دارید و یک عبارت را با شکل‌های مختلف پشت‌سرهم تکرار نکنید.
برای کلینیک‌ها، متن معرفی و اطلاعات تماس/خدمات باید دقیق و متعلق به همان کسب‌وکار باشد؛ اطلاعات حساس مشتری یا بیمار عمومی نشود.

## پس از وصل‌شدن دامنه

۱. در Production هر دو SITE_URL و NEXT_PUBLIC_SITE_URL را https://1ix.ir قرار دهید و دوباره Deploy کنید.
۲. ریدایرکت دامنه‌های جایگزین مثل www را در Vercel روی دامنهٔ اصلی تنظیم کنید.
۳. در Google Search Console، Domain property را با DNS خودتان تأیید کنید.
۴. sitemap.xml را ثبت کنید.
۵. URL Inspection را برای خانه، تعرفه‌ها و یک صفحهٔ کسب‌وکار منتشرشده اجرا کنید؛ HTML رندرشده، canonical و مجازبودن index را بررسی کنید.
۶. structured data را در ابزارهای معتبر تست کنید؛ وجود schema تضمین نمایش rich result نیست.
۷. عملکرد موبایل را روی دامنهٔ نهایی در PageSpeed Insights و Search Console بررسی کنید؛ امتیاز یا Core Web Vitals واقعی در محیط محلی اندازه‌گیری نشده‌اند.
۸. وضعیت ایندکس، خطاهای خزش، queryها و صفحات مؤثر را بعد از جمع‌شدن دادهٔ واقعی بررسی کنید.

Noindex و robots جایگزین احراز هویت نیستند؛ امنیت پنل در API و نشست بررسی می‌شود.
نتیجهٔ تست محلی به معنی ایندکس‌شدن یا رتبهٔ مشخص در Google نیست.
